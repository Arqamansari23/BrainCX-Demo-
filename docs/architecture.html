System architecture

VoiceCRM Architecture

A small CRM you can update by voice. Seven parts work together. The browser talks, LiveKit carries the audio, a Gemini-powered agent decides what to do, and the CRM API saves it, runs automations and tells everyone else.

Example used on this page: the sales rep clicks Talk to assistant and says “Move John Smith to Qualified and create a follow-up for tomorrow.”

  1. Get a ticket. The Talk button asks the CRM API for a LiveKit token (POST /api/livekit/token). The API checks the login cookie and returns a 10-minute token for a brand-new room crm-…. The token also says “send the agent named crm-agent”.
  2. Join the room. The browser connects to LiveKit Cloud with that token. Signalling uses a secure WebSocket on port 443, and the microphone audio flows as encrypted WebRTC packets over UDP, the same technology video calls use.
  3. The agent joins. LiveKit gives the job to the worker registered as crm-agent, our voice agent, which has been waiting since you started it. It joins the room and starts hearing you.
  4. Understand. The agent streams your voice to Gemini 3.1 Live. Gemini hears two requests and asks for two tools: move_deal_stage and create_follow_up.
  5. Act. Each tool is an HTTP call to the CRM API with the agent's secret key, for example PATCH /api/opportunities/1 {"stage": "qualified"}.
  6. Automate. In the same database transaction, the API runs the Qualified rule, which creates a “Prepare proposal” task due in 2 days.
  7. Save. Everything is written to PostgreSQL: the new stage, the tasks, and an activity row saying who did it (voice).
  8. Refresh. The API pushes a short message over the WebSocket /ws. The board reloads, John's card moves to Qualified, and a toast appears.
  9. Notify. After replying, the API sends a signed opportunity.stage_changed webhook to WEBHOOK_URL. An n8n workflow there could, for example, email the client.
  10. Answer. Gemini's spoken reply goes from the agent through LiveKit to your speakers: “Done, John Smith's Acme CRM rollout deal is now in Qualified, with a follow-up call for Friday. The pipeline automation also added a Prepare proposal task for Saturday.”

LiveKit room

Tech
LiveKit Cloud, a managed real-time media server
Address
wss://your-project.livekit.cloud. Signalling on port 443; audio over WebRTC (UDP, with a TLS 443 fallback)
Does
Hosts one private room per conversation. Carries your voice to the agent, the agent's voice back, live transcripts and agent state. Sends crm-agent into the room.
src/crm_api/routes.py → livekit_token().env.local → LIVEKIT_URL / KEY / SECRET

The CRM API mints the room token. The server picks the room, the identity and the agent, so the browser can't choose another room or agent.

# src/crm_api/routes.py (shortened)
room = f"crm-{secrets.token_hex(4)}"            # a new private room every time
token = (
    AccessToken(LIVEKIT_API_KEY, LIVEKIT_API_SECRET)
    .with_grants(VideoGrants(room_join=True, room=room))
    .with_room_config(RoomConfiguration(
        agents=[RoomAgentDispatch(agent_name="crm-agent")]))  # send our agent
    .with_ttl(timedelta(minutes=10))
)
return {"server_url": LIVEKIT_URL, "participant_token": token.to_jwt()}

async def get_actor(conn, x_api_key: str | None = Header(default=None)):
    if x_api_key is not None:
        if AGENT_API_KEY and _same(x_api_key, AGENT_API_KEY):
            return "voice"                 # the voice agent's key
        raise HTTPException(401, "Invalid API key")

CREATE TABLE opportunities (
    id          SERIAL PRIMARY KEY,
    contact_id  INT NOT NULL REFERENCES contacts(id) ON DELETE CASCADE,

Webhooks and live refresh

These are two different things. The page refresh uses a WebSocket, a connection the browser keeps open to our API. Webhooks are how the CRM talks to outside tools like n8n.

Live refresh (WebSocket /ws on :8001, through :5174)

After every saved change, the API sends a small message to every open tab. The tab reloads GET /api/board, shows a toast and highlights the card.

src/crm_api/realtime.pysrc/crm_api/main.py → /wsweb/src/live.tsx
# API, after the transaction commits (routes.py)
await hub.broadcast({"type": "crm", "actor": "voice",
                     "summary": "John Smith: Acme CRM rollout moved from Contacted to Qualified"})

// browser (web/src/live.tsx)
socket.onmessage = (m) => { const e = JSON.parse(m.data); if (e.type === "crm") refresh(); };

Outbound webhooks to n8n (2 events)

opportunity.stage_changed and lead.created are POSTed to WEBHOOK_URL, for example an n8n Webhook node that sends the client an email. They're signed with WEBHOOK_SECRET and sent after the reply, so they never slow the agent down.

src/crm_api/automations.py → deliver_webhook().env.local → WEBHOOK_URL
# src/crm_api/automations.py (shortened)
headers = {
    "X-Event": event,                                  # opportunity.stage_changed
    "X-Timestamp": timestamp,
    "X-Signature": sign(WEBHOOK_SECRET, timestamp, body),   # sha256=HMAC(...)
}
await client.post(WEBHOOK_URL, content=body, headers=headers)

Inbound webhook (1 endpoint)

Website forms, Zapier or n8n can send new leads to POST /api/webhooks/leads, signed with INBOUND_WEBHOOK_SECRET.

  • A bad or old signature gets 401.
  • A repeat of the same request gets 409.
  • A body over 10 KB gets 413.
  • A valid lead gets 201, and the Intro call automation runs.
